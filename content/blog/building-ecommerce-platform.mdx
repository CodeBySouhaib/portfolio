# Building Soukify: A Multi-Vendor E-Commerce Marketplace

During my PFE internship at **Awel**, I built **Soukify** — a full-featured B2B multi-vendor marketplace from scratch. Not a simple CRUD app, but a real platform with 37 database entities, 3 user roles, real-time chat, quote/invoice generation, and a commission tracking system.

Here's the technical deep dive into what I built and what I learned.

## The Scale

Before diving in, let me give you an idea of the scope:

- **37 Entity Models** — Users, Products, Orders, SubOrders, Devis (Quotes), Factures (Invoices), Chat messages, and more
- **3 User Roles** — Admin, EntrepriseAdmin, Client with distinct permissions
- **25+ API Controllers** — Organized into Admin, Auth, Catalog, Client, and Entreprise modules
- **Real-time Features** — SignalR-powered chat with delivery/seen status
- **PDF Generation** — Automated quotes and invoices
- **Mobile Ready** — Capacitor integration for Android/iOS

## Multi-Vendor Architecture

The core challenge was designing a system where multiple **Entreprises** (vendors) can operate independently while sharing a unified storefront.

When a new admin requests to join an enterprise, the owner must approve them. This prevents unauthorized access to vendor dashboards and inventory.

## Real-Time Chat with SignalR

The chat system was one of the most complex features. Users can message vendors directly, and conversations can be **product-specific**.

### ChatHub Implementation

```csharp
public class ChatHub : Hub
{
    public async Task SendMessage(int receiverId, string content)
    {
        var senderId = GetUserIdFromApiKey();
        var message = new ChatMessage
        {
            SenderId = senderId,
            ReceiverId = receiverId,
            Content = content,
            SentAt = DateTime.UtcNow,
            IsDelivered = false,
            IsSeen = false
        };
        
        await _context.ChatMessages.AddAsync(message);
        await _context.SaveChangesAsync();
        
        // Real-time delivery to recipient
        await Clients.User(receiverId.ToString())
            .SendAsync("ReceiveMessage", message);
    }

    public async Task SendMessageWithProduct(
        int receiverId, 
        string content, 
        int productId)
    {
        // Same as above, but with product context
        // Allows "Ask about this product" feature
    }

    public async Task MarkMessageAsSeen(int messageId)
    {
        var message = await _context.ChatMessages.FindAsync(messageId);
        message.IsSeen = true;
        message.SeenAt = DateTime.UtcNow;
        await _context.SaveChangesAsync();
        
        // Notify sender that their message was seen
        await Clients.User(message.SenderId.ToString())
            .SendAsync("MessageSeen", messageId);
    }
```

```typescript
export const useChatStore = defineStore('chat', {

        .build();
        
      this.connection.on('ReceiveMessage', (message) => {
        this.handleIncomingMessage(message);
      });
      
      this.connection.on('MessageSeen', (messageId) => {
        this.markLocalMessageAsSeen(messageId);
      });
      
      await this.connection.start();
    }
  }
});
```

## Smart Product Filtering

The filtering system goes beyond basic category filters:

```csharp
[HttpGet("filter")]
public async Task<IActionResult> FilterProducts(
    [FromQuery] int? domainId,
    [FromQuery] int? categoryId,
    [FromQuery] decimal? minPrice,
    [FromQuery] decimal? maxPrice,
    [FromQuery] bool? hasDiscount,
    [FromQuery] bool? inStock,
    [FromQuery] decimal? minRating,
    [FromQuery] string? sortBy,  // price, rating, bestseller, newest, mostViewed
    [FromQuery] int page = 1,
    [FromQuery] int pageSize = 20)
{
    var query = _context.Products
        .Include(p => p.Category)
        .Include(p => p.Entreprise)
        .AsQueryable();
    
    // Apply filters...
    
    // Recommendation algorithm for "recommended" sort
    if (sortBy == "recommended")
    {
        query = query.OrderByDescending(p => 
            (p.ViewCount * 0.3) + 
            (p.AverageRating * 0.4) + 
            (p.OrderCount * 0.3));
    }
    
    return Ok(await query.ToPagedListAsync(page, pageSize));
}
```

## Notification System

Users can **follow enterprises** and get notified when new products are added:

```csharp
public class NotificationService
{
    public async Task NotifyFollowersOfNewProduct(Product product)
    {
        var followers = await _context.EntrepriseFollowers
            .Where(f => f.EntrepriseId == product.EntrepriseId)
            .Select(f => f.UserId)
            .ToListAsync();
        
        foreach (var userId in followers)
        {
            await CreateNotification(userId, 
                $"New product from {product.Entreprise.CompanyName}: {product.Name}",
                NotificationType.NewProduct,
                product.Id);
        }
    }
}
```

Users can also **subscribe to out-of-stock products** and get notified when they're back in stock.

## Lessons Learned

### 1. Design for Multi-tenancy Early
The SubOrder pattern for splitting orders per vendor was a late addition. It required significant refactoring. Plan for multi-vendor complexity from day one.

### 2. Real-time Features Need Careful State Management
SignalR is powerful but managing connection state, reconnection logic, and message synchronization across tabs/devices is complex. Pinia's reactive stores were essential.

### 3. PDF Generation is Harder Than It Looks
Generating professional-looking invoices with proper formatting, localization (French/Arabic), and correct tax calculations took more time than expected.

### 4. Commission Tracking Needs Audit Trail
Every financial transaction needs timestamps, actor IDs, and status history. The `CommissionLog` model evolved multiple times to capture all necessary audit data.

### 5. Type Safety Pays Off
Using TypeScript on the frontend and strong typing in C# caught countless bugs at compile time. The Pinia stores with proper TypeScript interfaces made refactoring safe.
